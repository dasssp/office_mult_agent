# 企业 Multi-Agent 办公助手需求说明

更新时间：2026-07-28

## 1. 建设目标

系统面向企业内部办公场景，提供一个可规划、可委派、可审核、可恢复、可审计的
Multi-Agent 办公助手。主 Agent 负责理解目标、拆解任务、委派领域子 Agent、有限
重规划和结果汇总；领域子 Agent 只能调用所属领域的受控工具。

系统不在 Python 应用中重复实现 Java RAG。知识能力通过 LangChain MCP Client 和
Streamable HTTP 直接调用 Java RAG 暴露的 MCP Server。

## 2. Agent 架构需求

### 2.1 主 Agent

主 Agent 必须具备：

- 对简单任务直接委派，对复杂任务生成和维护 TODO；
- 在日报、会议、邮件、数据分析和知识检索子 Agent 之间动态委派；
- 只接收子 Agent 的结构化摘要、证据引用和产物引用；
- 子任务失败时进行有限重规划，不得进入无界反思循环；
- 汇总部分成功结果，并明确失败、阻塞和待确认项；
- 不直接执行报告提交、邮件发送、文件删除等外部写操作。

### 2.2 领域子 Agent

系统提供以下白名单子 Agent：

- `report-agent`：并行聚合 GitLab、任务、已发送邮件摘要和已审核会议纪要，完成
  日报周报生成、审核和受控提交；
- `meeting-agent`：会议信息、ASR 长任务、纪要生成、审核和受控发送；
- `email-agent`：邮件问题检查、敏感信息识别和草稿润色；
- `data-agent`：受控文件分析、指标计算、图表与报告导出；
- `knowledge-agent`：通过 Java RAG MCP 查询企业知识并返回引用；
- `general-purpose`：仅允许整理已有内容，不得执行领域业务。

每个子 Agent 必须配置最小工具集，不得默认继承其他领域工具。

## 3. 上下文与记忆需求

- 对话和工作区短期状态按 `thread_id` 通过 Checkpointer 保存；
- 大型工具输出卸载到线程级虚拟工作区，主上下文只保留摘要与引用；
- 长对话由 Deep Agents 自动摘要，避免消息无限增长；
- 长期记忆按租户和用户隔离；
- 只有用户明确确认的偏好才能写入长期记忆；
- 企业策略为只读数据，不能被模型或文档内容修改；
- Token、密码、完整文件、录音和敏感正文不得写入日志或长期记忆。

## 4. 安全与治理需求

所有外部写操作必须依次执行：

1. 可信身份解析；
2. 租户边界检查；
3. 权限检查；
4. 人工审核；
5. 业务状态校验；
6. 敏感信息检查；
7. 幂等检查；
8. Connector 写入；
9. 状态回查；
10. 审计记录。

身份、租户和权限必须通过 `ToolRuntime[RequestContext]` 注入，不得成为模型可填写参数。

上传文件不得执行宏、脚本、公式或外部链接。需要自由代码执行的数据任务必须部署在
独立沙箱中，限制网络、CPU、内存、运行时间和可访问文件。

## 5. 持久化与恢复需求

- 开发环境允许使用内存 Checkpointer 和 Store；
- 数据库环境使用 PostgreSQL 保存业务记录、Agent Checkpoint 和 Store；
- Redis 仅缓存可重建的热点读数据，缓存键必须按租户、用户和权限范围隔离；
- 缓存不可用时必须回源，审批、提交、审计、Checkpoint 和任务状态不得以缓存为事实源；
- 多数据源报告中单个只读来源不可用时，应保留其他来源结果并提示缺失来源；
- 邮件进入报告前必须过滤敏感标记，不得采集完整邮件正文；
- HITL 中断后必须可以使用同一个 `thread_id` 恢复；
- 审核记录只能消费一次；
- 进程重启或请求重放不能导致重复提交、重复发送；
- ASR 等长任务必须采用启动、查询、取消或失败终止的非阻塞模型。

## 6. API 兼容需求

- 保留现有 `/assistant/invoke`、`/assistant/{thread_id}/resume` 和领域 API；
- 生产环境必须显式配置 `AGENT_MODEL`，不得静默降级到另一套编排；
- 开发环境未配置模型时，Assistant API 必须明确返回不可用，领域 API 保持可测试；
- API 响应继续提供状态、结果、警告和审核状态，不返回隐藏推理过程；
- 审核状态接口应返回待执行工具及对应权限范围。

## 7. 验收标准

- 主 Agent 能完成至少三条跨领域任务链；
- 子 Agent 工具集互相隔离；
- 写操作未经正确权限和人工确认无法执行；
- 长对话和大工具结果不会完整堆积在主 Agent 消息中；
- 确认记忆在不同线程可恢复且不同租户不可见；
- PostgreSQL 模式下中断后重启可以恢复；
- GitLab 活动、知识问答和确认记忆的重复读取能够命中缓存且不发生跨租户/权限泄漏；
- 日报能够聚合 GitLab、任务、邮件摘要和已审核会议纪要，并保留来源引用；
- Mock 与真实 Connector 边界明确；
- `pytest`、`ruff check .` 和 `mypy app` 通过。
